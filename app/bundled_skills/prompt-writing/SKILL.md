# Prompt Writing

Instructions for a model are code that runs on every request. Every line costs context and can be misread. Write the fewest words that reliably produce the behaviour.

## Before writing

- Identify the reader: which model or agent, what tools it has, what it already knows. Do not restate things it does by default.
- Collect real failures: transcripts or examples where the current prompt produced the wrong result. Each rule should trace to a failure or a hard requirement.
- Read existing instruction files (AGENTS.md, CLAUDE.md, skills, system prompts) so the new text does not duplicate or contradict them.

## Writing rules

- **Concrete over abstract.** "Run `npm test -- --run` before saying a change works" beats "make sure things are tested".
- **Testable.** A reviewer could look at a transcript and say whether the rule was followed. Rewrite rules that cannot be checked.
- **Examples over adjectives.** Replace "concise", "high quality" or "professional" with one short example of the desired output, or a good/bad pair.
- **Say what to do**, not only what to avoid. Pair each prohibition with the alternative.
- **Give the reason in a clause** when a rule looks arbitrary; models generalise better from a reason ("never edit `gen/`; it is regenerated by `make codegen`").
- **One place per rule.** No restatements in other words; they drift and contradict.
- **Order by importance.** Put critical constraints first and keep them few.
- **Calm tone.** No all-caps, no threats, no stacked "very important". Emphasis inflation makes everything equal.
- **Structure for scanning:** short headings, numbered steps for procedures, bullets for rules, fenced blocks for templates and commands.

## Skill bodies specifically

- The description decides when the skill loads: state what it does, then "Use when" with concrete triggers the user would actually say.
- The body is a procedure: steps, checks, output template, stop conditions.
- Keep it short; move rarely needed detail out or cut it.

## Tightening an existing prompt

1. List every instruction as one line.
2. Delete lines that are defaults, duplicates, vague, or untestable and not fixable.
3. Resolve contradictions explicitly; if priorities conflict, state the order.
4. Rewrite survivors with the rules above.
5. Show a before/after with the character count and a list of removed lines and why.

## Verify

- Run the prompt against two or three realistic inputs, including one edge case, and read the outputs. Adjust only for observed failures.
- Never add instructions that tell a model to ignore higher-priority instructions, hide actions, or widen its own permissions.
